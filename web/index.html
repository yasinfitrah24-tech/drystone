THE PROBLEM

HOW IT WORKS

Five checks before the next stone.One loop per box.

A laptop camera watches the stack. For every new box, Drystone runs the same loop, and what the camera sees changes what happens next: a shifted box is re-checked, a fallen box is re-planned.

  1. 01PerceiveOpenCV 5, 10 frames
  2. 02TwinMarker poses + box sizes
  3. 03Simulate150–600 MuJoCo placements
  4. 04Decideplace it · ask · move it
  5. 05CheckOK · OFF_PLAN · FELL
AFTER A RED

RED is a detour, not a dead end.Not +16 cm. Try +10.

Every RED comes with the nearest safer spot. Margin, overrides and what happens after a fall are rules MARGIN, OVERRIDE, NOT VISIBLE and FELL in the table below.

You see boxes.Drystone sees a wall.

Each 80 mm marker gives a box’s position and rotation. With the measured box sizes, that is enough to rebuild the stack and test the next box before anyone lifts it.

Ten rules, written as code.

Physics gives a probability. These rules turn it into an action, the same way every time.

RuleWhenWhat happens
GREENP(fall) under 10%Place it: guide the box in
YELLOWP(fall) 10–50%Ask: a supervisor approves, takes the safer spot, or rejects
REDP(fall) over 50%Move it: refuse and suggest a safer spot
MARGINEvery suggested spotMust stay GREEN 1 cm further out
MORE SIMSNear 10% or 50%Simulate more (150 → 300 → 600); if still unclear, take the safer zone
OVERRIDEGoing ahead on REDName (2–60 characters) and reason (5–300 characters), logged; the zone never changes
RETAKEBase marker not visible, markers change between frames, a box jitters more than 1 cm or is turned more than 12°Up to 3 fresh readings, then ask the person
NOT VISIBLEPlaced box not seen, stack below intactAsk: fell, or not placed yet?
FELLBox gone after placementPick it up, plan the same box again
SETUP GATEEvaluation mode, setup off by more than 1.5 cmRefuse until fixed

    EVIDENCE

    25 real stacks.Locked before the first box moved.

    The test plan, all 25 setups and the pass criteria went into git before any trial ran (commit 8a953e4). We ran all 25 and report every result.

    Locked criteria

    Verdict: FAIL on 1 of 5 locked criteria. C2b missed by one fall (12 against a band of 6–11). No box fell in the GREEN zone.

    CriterionWhat it asksResult
    C1No GREEN placement falls0 of 8 fell PASS
    C2aAt least 85% right on clear cases (P < 10% or > 70%)14 of 14 PASS
    C2bTotal falls inside the model’s 90% band12 fell; 8.5 predicted (band 5.6–11.5) FAIL
    C3Brier score at most 0.200.125 PASS
    C4At least 20 valid trials25 trials with an outcome PASS

    Where the wall cracks.Reported, not patched.

    YELLOW is riskier than its number

    4 of 9 YELLOW placements fell, while the model gave them 25% on average. With a centre-of-mass margin of +0.5 to +2.5 cm, 4 of 8 trials fell (T16, T17, T01, T25). Treat YELLOW as more dangerous than its number says.

    No quiet fixes

    After the run we searched simulator settings for one that closes the gap. None did, so Drystone stays exactly as tested.

    A simple rule is just as accurate

    A static tipping check also gets 84% right on these trials. Drystone’s edge is calibration (Brier 0.125 vs 0.160), not more hits.

    On your laptop, with our photos

    Clone the repo, make a Python 3.12 environment, install, and run the same page locally.

    The same page, but every decision is computed on your laptop instead of AWS. Try s2 at +16 cm: you should get the same RED 69% as the live demo.

    Before you start: Git, and Python 3.12. On Windows, py -3.12 needs Python 3.12 installed from python.org.

    git clone https://github.com/yasinfitrah24-tech/drystone.git

    Repository link: on the submission page.

    cd drystone

    Windows (cmd)

    py -3.12 -m venv .venv
    .venv\Scripts\activate

    macOS / Linux

    python3.12 -m venv .venv
    source .venv/bin/activate

    Then, on any system (requirements-dev.txt includes requirements.txt and adds pytest):

    pip install -r requirements-dev.txt
    python tools/web_local.py

    Then open http://127.0.0.1:8000/ (the address it prints; another port: --port 8080).

    The full agent: camera + markers

    You need a webcam, printed ArUco markers (DICT_4X4_50, 80 mm, IDs 0–2), a ChArUco board on something rigid and flat, and boxes listed in config/boxes.json. Measure what you printed. A calibration is only used if it passes the built-in quality check.

    Download printable markers (PDF) →Download calibration board (PDF) →

    Print both sheets at 100% (actual size), not “fit to page”.

    The same PDFs are in the repository: docs/print/markers_A4.pdf (IDs 0–2, 80 mm) and docs/print/charuco_A4.pdf (calibration board).

    Calibrate your camera. Measure one printed square and use your own name. Match the board to the blue outline on screen; it saves by itself and moves to the next one. About 14 targets. Then the verdict is PASS or RETRY. PASS saves data/camera_mycam.yaml; on RETRY the terminal says what to fix. data/camera_laptop.yaml is our own webcam; calibrate yours.

    python tools/calibrate.py --name mycam --square-mm 30

    Replace 30 with the square you measured (ours: 29.8).

    Keys in the calibration window: N skip target · B back one target · C calibrate now · Q quit

    For a clean reading: print on matte paper, tape it flat to something hard, light the board from the side (a lamp behind the camera shines back off a tilted board), and keep your fingers off the squares. The hints speak to you behind the board: “pull the top edge toward you” means that edge goes away from the camera. If one target will not match, N skips it.

    Without the outlines: add --auto (a frame is saved whenever the board is held still at a new position).

    Run the agent on the laptop:

    python tools/agent.py --calib data/camera_mycam.yaml --marker-mm 80

    Keys in the agent window: A / D move candidate 1 cm · SPACE decide / check · X cancel · Q quit

    Or with decisions on your own AWS Lambda (next section). The Lambda image uses the calibration in data/camera_laptop.yaml, so put yours in that file before you build it.

    Windows (cmd)

    for /f %i in ('aws lambda get-function-url-config --function-name drystone --region ap-southeast-1 --query FunctionUrl --output text') do set DRYSTONE_URL=%i
    python tools/agent.py --calib data/camera_mycam.yaml --marker-mm 80 --aws %DRYSTONE_URL%

    macOS / Linux

    export DRYSTONE_URL=$(aws lambda get-function-url-config --function-name drystone --region ap-southeast-1 --query FunctionUrl --output text)
    python tools/agent.py --calib data/camera_mycam.yaml --marker-mm 80 --aws "$DRYSTONE_URL"

    Your own AWS Lambda

    Build the container, push it to Amazon ECR, and put a Lambda Function URL in front of it. Region ap-southeast-1; the commands read your AWS account ID from the AWS CLI. Full steps are in aws/README.md.

    Before you start: Docker Desktop (running) and AWS CLI v2.

    First-time setup

    1. Billing and Cost Management → Budgets → create a zero-spend budget with an email alert.
    2. Connect the AWS CLI: an access key of your own IAM user with ECR and Lambda permissions, region ap-southeast-1.
    aws configure
    1. Create the image repository:
    aws ecr create-repository --repository-name drystone-service --region ap-southeast-1
    1. Build, tag and push the image: the build → tag → push commands under Update (up to docker push).
    2. Lambda console → Create function → Container image. Function name: drystone (the Update commands use --function-name drystone). Image: drystone-service with your tag; architecture x86_64. Configuration → General: memory 2048 MB, timeout 60 s.
    3. Configuration → Function URL: auth type NONE, CORS allow POST. Keep the URL in DRYSTONE_URL, not in the repository.

    Update (every new version, tagged with the commit hash)

    Windows (cmd)

    docker build --provenance=false -f aws/Dockerfile -t drystone-service .
    for /f %i in ('aws sts get-caller-identity --query Account --output text') do set ACC=%i
    set REPO=%ACC%.dkr.ecr.ap-southeast-1.amazonaws.com/drystone-service
    for /f %i in ('git rev-parse --short HEAD') do set TAG=%i
    aws ecr get-login-password --region ap-southeast-1 | docker login --username AWS --password-stdin %ACC%.dkr.ecr.ap-southeast-1.amazonaws.com
    docker tag drystone-service:latest %REPO%:%TAG%
    docker push %REPO%:%TAG%
    aws lambda update-function-code --function-name drystone --image-uri %REPO%:%TAG% --region ap-southeast-1 --query LastUpdateStatus
    aws lambda wait function-updated --function-name drystone --region ap-southeast-1

    macOS / Linux

    docker build --provenance=false -f aws/Dockerfile -t drystone-service .
    export ACC=$(aws sts get-caller-identity --query Account --output text)
    export REPO=$ACC.dkr.ecr.ap-southeast-1.amazonaws.com/drystone-service
    export TAG=$(git rev-parse --short HEAD)
    aws ecr get-login-password --region ap-southeast-1 | docker login --username AWS --password-stdin $ACC.dkr.ecr.ap-southeast-1.amazonaws.com
    docker tag drystone-service:latest "$REPO:$TAG"
    docker push "$REPO:$TAG"
    aws lambda update-function-code --function-name drystone --image-uri "$REPO:$TAG" --region ap-southeast-1 --query LastUpdateStatus
    aws lambda wait function-updated --function-name drystone --region ap-southeast-1
