THE PROBLEM

Every stack is a judgement call,made by eye.

How far can the next box hang over the one below? When boxes are stacked by hand, a person answers that by eye, and a wrong guess only shows when the stack comes down.

The rules are the gate, not the model.

Fixed rules in one file (drystone_core.py) turn P(fall) into an action. No language model makes a decision. The same code runs on the laptop and on AWS Lambda.

OpenCV 5

80 mm ArUco markers (DICT_4X4_50), sub-pixel corners, solvePnPGeneric. ChArUco calibration: 61 views, RMS 0.37 px.

MuJoCo

Monte Carlo, 150–600 simulated drops with 1 cm position and 2 cm load uncertainty; more runs near a zone line.

AWS Lambda + ECR + CloudWatch

Container image (2048 MB, 60 s) tagged with the git commit; supervisor choices are one JSON line in CloudWatch Logs.

Budget alarm

A zero-spend budget alarm sends an email at the first cent. 60 GET and 20 POST a minute per IP.

HOW IT WORKS

Five checkpoints between the camera and the next box.

The camera measures. The simulation estimates. The rules decide. A person places every box.

  1. 1Perceive

    10 frames; 80 mm ArUco markers with sub-pixel corners; pose with solvePnPGeneric. A shaky reading is taken again (up to 3 times).

  2. 2Digital twin

    The stack is built by contact, from the bottom box up, with the measured box sizes and weights from config/boxes.json.

  3. 3Simulate

    MuJoCo Monte Carlo: 150–600 drops of the next box with 1 cm position and 2 cm load uncertainty.

  4. 4Decide

    GREEN under 10% guides, YELLOW 10–50% asks a supervisor, RED over 50% rejects and suggests a safer spot.

  5. 5Check

    After placement the camera reads the stack again: OK, OFF_PLAN (more than 1.5 cm off) or FELL.

What the camera reads

RED is not the end. Get a safer spot.

A suggested spot must be green where it is and 1 cm further out, because real placements landed 0.0–1.3 cm from the plan. A real trace from the final practice (18 Oct, decision on Lambda):

150 simulations: P(fall) = 93% +- 4%
not green -> searching the nearest safe position
try +12 cm (+41%): P = 15%
try +11 cm (+38%): P = 12%
try +10 cm (+34%): P = 4%, but 1 cm further out (+11 cm P = 12%) is not green -> no margin, keep looking
try +9 cm (+31%): P = 1%; 1 cm further out (+10 cm P = 4%) also green -> suggestion

If a box falls anyway, the check sees it on the floor and the agent plans it again. The final scene of the practice:

  1. RED 93% → override (name and reason logged)
  2. The box fell → check: FELL
  3. “Pick it up” → the same box is planned again
  4. RED again → suggestion +9 cm
  5. Check OK (−0.3 cm), stack GREEN 1%

    EVIDENCE

    Locked evaluation, 25 new trials.

    Protocol locked in git before any data (commit 8a953e4): 25 pre-set trials in a shuffled order, settings frozen, every outcome confirmed by the worker. All 25 ran on 18 Oct in 26 minutes.

    Verdict: FAIL under the locked criteria, because of C2b: one fall more than the upper end of the interval (z = 1.96). The model under-predicts falls. Four of five criteria passed.

    Locked criteria

    Criterion (locked)ResultTarget
    C1 falls in the GREEN zone0 of 8 GREEN trials0PASS
    C2a accuracy on clear trials (P < 10% or > 70%)14/14 (100%)≥ 85%PASS
    C2b total falls inside the 90% interval of the predicted number12 falls; Σp = 8.537, sd 1.772, interval 5.62–11.45 → 6–11insideFAIL
    C3 Brier score0.125≤ 0.20PASS
    C4 trials with an outcome25 of 25≥ 20PASS

    A calibrated model with these P would see 12 or more falls only 4.7% of the time. Overall accuracy (P ≥ 50% predicts a fall), not a criterion: 84% (21/25), against 82% in Test 2.

    The check after placement agreed with the outcome the worker confirmed in 25/25 trials, and detected 12/12 falls as FELL (7/7 in the practice). Decisions on AWS Lambda: median 7.6 s, max 11.1 s.

    Failure cases

    The four wrong predictions are all YELLOW trials that fell:

    TrialStackShiftCentre-of-mass marginP(fall)Outcome
    T163 boxes, ID 1 at −4.6 cm+12 cm+2.5 cm14%fell
    T173 boxes, ID 1 at −0.2 cm−12 cm+2.5 cm17%fell
    T012 boxes+14 cm+0.5 cm35%fell
    T253 boxes, ID 1 at +5.2 cm+14 cm+0.5 cm43%fell

    Every trial with a margin of −0.5 cm or less fell (8/8, all predicted RED); every trial with +3.5 cm or more stood (9/9). In between, from +0.5 to +2.5 cm, 4 of 8 fell while the model predicted 12–43%: the model ranks the risk correctly and keeps GREEN safe, but it is too optimistic in the middle band. A post-hoc check of nine other simulation settings (not used by the system) found no setting that fixes it: Brier 0.121–0.132.

    Limits & responsible use

    • Markers are required on every box; faded markers in dim light can be missed.
    • One calibration per camera and resolution; the service is calibrated for one webcam at 1280×720.
    • Three measured boxes of one type (29 × 17 × 19.4–19.6 cm, 1.0 kg, load in the middle); other boxes, uneven or soft loads are untested.
    • The model under-predicts falls near the edge. Treat YELLOW as more dangerous than its number says.
    • On the evaluation trials the simulation is no more accurate than a static centre-of-mass check (both 84%); it is better calibrated (Brier 0.125 vs 0.160).
    • Small samples: Test 2 has 11 counted trials; the evaluation has 25.
    • Use Drystone to support a person’s judgement, never as the only safeguard. It is not certified for safety.
    • Keep people, hands and the laptop out of the direction a box can fall when testing risky placements.
    • Overrides exist so that a person stays in charge; they are logged with a name and a reason.
    • Logs and photos show people and rooms; they stay on the laptop. Published data has no photos and no names.

    SETUP

    Four ways to run Drystone.

    Windows Command Prompt, Python 3.12, from the repository folder. One command per line.

    1

    On the web, nothing to install

    Open the Demo tab: pick a sample photo and tap a spot on the ruler. The check runs on AWS Lambda.

    2

    On your laptop, with the sample photos

    Same handler as Lambda, no camera needed.

    git clone <repository URL>
    cd drystone
    python -m venv .venv
    .venv\Scripts\activate
    pip install -r requirements-dev.txt
    python tools/web_local.py

    Then open http://127.0.0.1:8000/. Run the tests with:

    python -m pytest tests -q
    3

    Full: webcam, real boxes and printed markers

    This level needs real things: cardboard boxes, a printed 80 mm ArUco marker (DICT_4X4_50, IDs 0–11) in the middle of each box’s front face, and a webcam. Print assets/opencv_marker_kalibrasi.pdf, glue the ChArUco board to a flat hard board and measure the square size. List your boxes (size and weight per marker ID) in config/boxes.json.

    Calibrate your camera; repeat until the verdict is LAYAK:

    python tools/calibrate.py --name laptop --square-mm 29.8 --auto

    Run the agent on the laptop:

    python tools/agent.py --calib data/camera_laptop.yaml --marker-mm 80

    Or with decisions on AWS Lambda (your own deployment, level 4):

    set DRYSTONE_URL=<your Function URL>
    python tools/agent.py --calib data/camera_laptop.yaml --marker-mm 80 --aws %DRYSTONE_URL%
    4

    Deploy your own Lambda

    Container image in Amazon ECR, Lambda x86_64, 2048 MB, 60 s, Function URL. First time: create the ECR repository drystone-service, then create the function from the image in the console. Docker Desktop must be running.

    docker build --provenance=false -f aws/Dockerfile -t drystone-service .
    for /f %i in ('aws sts get-caller-identity --query Account --output text') do set ACC=%i
    for /f %i in ('git rev-parse --short HEAD') do set TAG=%i
    set REPO=%ACC%.dkr.ecr.ap-southeast-1.amazonaws.com/drystone-service
    aws ecr get-login-password --region ap-southeast-1 | docker login --username AWS --password-stdin %ACC%.dkr.ecr.ap-southeast-1.amazonaws.com
    docker tag drystone-service:latest %REPO%:%TAG%
    docker push %REPO%:%TAG%
    aws lambda update-function-code --function-name drystone --image-uri %REPO%:%TAG% --region ap-southeast-1 --query LastUpdateStatus
    aws lambda wait function-updated --function-name drystone --region ap-southeast-1

    The account is billed above the always-free quota: keep a zero-spend budget alarm on. Full notes: aws/README.md.
